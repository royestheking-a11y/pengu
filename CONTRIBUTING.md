# Contributing to Pengu AI

Welcome! We're excited that you're interested in contributing to Pengu AI. To maintain a high standard of quality and keep our development process organized, we follow a professional open-source workflow.

## 🚀 Workflow Overview

We follow an **Issue-Driven Development** and **Branch-based Workflow**. This ensures every change is documented, reviewed, and tested.

### 1. Find or Create an Issue
Before writing any code, ensure there is an issue that describes the work.
- Check the [Issues](https://github.com/royestheking-a11y/pengu/issues) tab to find something to work on.
- If you have a new idea or found a bug, [create a new issue](https://github.com/royestheking-a11y/pengu/issues/new/choose) first.

### 2. Create a Branch
Always work on a new branch. Never commit directly to `main`.
- Name your branch using the format: `feature/description` or `fix/description`.
- Example: `git checkout -b feature/seo-optimization`

### 3. Commit and Push
Make your changes and commit them with descriptive messages.
- `git commit -m "feat: add meta tags for better SEO"`
- `git push origin feature/seo-optimization`

### 4. Open a Pull Request (PR)
Once your changes are pushed, go to GitHub and open a Pull Request.
- Link the PR to the issue it solves (e.g., "Closes #12").
- Provide a summary of your changes and any testing performed.

### 5. Code Review
Every PR should be reviewed. Even if you are working alone, use the PR description and comments to document your design decisions. This helps future maintainers (and your future self!) understand the "why" behind the code.

## 🎨 Design Guidelines

- **Rich Aesthetics**: We aim for premium, modern web design. Use curated color palettes, smooth transitions, and subtle animations.
- **Visual Excellence**: Avoid browser defaults. Use modern typography (e.g., Inter, Outfit) and HSL-based colors.
- **Responsiveness**: Ensure all features work flawlessly on mobile and desktop.

## 🛠 Tech Stack

- **Frontend**: React (Vite/TypeScript) + Vanilla CSS / Tailwind (where specified).
- **Backend**: Node.js / Express.
- **Styling**: Modern CSS with glassmorphism and dynamic hover effects.

## 📝 Commit Convention

We follow a basic version of Conventional Commits:
- `feat:` for new features.
- `fix:` for bug fixes.
- `docs:` for documentation changes.
- `refactor:` for code changes that neither fix a bug nor add a feature.
- `chore:` for updating build tasks, package manager configs, etc.
